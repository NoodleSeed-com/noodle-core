How to read these wireframes

UI Solid-border phones are the ChatGPT App (the Noodle Seed MenuCart widget rendered inline). Dashed-border phones are off-app — reached only after the payment hand-off, on Acme's own checkout. Every widget is preceded by its tool-call chip so you can see exactly which tool the model invoked.

TRUST The app never guesses and never touches a card. Menu, prices, and totals are grounded in the show_menu data; the diner's card is entered only on the amber off-app checkout. This is the whole safety story of the app, and it is visible in the pixels.

Capability · Order building
Build the order in language, confirm it in pixels
The whole menu, the cart, the running total, and the pay button live in one inline widget. The diner drives it two ways — by talking to the model or by tapping the steppers — and both land in the same place.

Why this approach

ACME One kitchen, one widget. A single restaurant with five items doesn't need discovery, carousels, or a fullscreen menu — it needs the fastest path from craving to a confirmed cart. MenuCart collapses menu, cart, and checkout into one card the diner never scrolls out of.

UX Language is the input; the widget is the receipt. "Two margheritas and a lemon tart" parses into two add_to_cart calls — no tapping required — and the widget instantly shows the result so the diner can trust what the model heard. Editing works the same in both directions.

UI Inline Card, brand accent on the CTA only. Acme red (#B91C1C) appears only on the header mark and the Check out & pay button; everything else uses host theme tokens via cascade layers, so the widget is native in ChatGPT light or dark. No nested scroll — five rows fit.

TRUST The total is honest and display-only. The widget sums line items live, but the amount that charges is recomputed by Acme at checkout. The reassurance line ("your card is never entered in chat") is present in every frame, not just the last one.

Capability · The one handoff
Payment is the only step that leaves ChatGPT
When the order is right, create_checkout mints a signed, expiring link carrying the cart token, the total, and an attribution tag. ChatGPT opens Acme's own PCI checkout. The MCP server is never in the payment path.

Why this approach

TRUST The card never touches the app. No in-chat card field, no wallet, no stored payment method. Keeping capture on pay.acme.example means the ChatGPT surface adds zero PCI scope — the single most important safety property of the design.

ACME The link is signed, expiring, and attributable. Acme signs the URL server-side, sets an expires_at (proposed 15 min), and carries src=chatgpt so ChatGPT-sourced revenue is measurable. handoff.allowedDomains lists pay.acme.example and acme.example so the compiler derives the redirect domain and the link opens without a safe-link warning.

UX Context survives the jump. The cart token (stone_pizzax2-lemon_tartx1-sparklingx1) rehydrates the exact order on Acme's checkout — the diner never re-enters what they already told the model. State is re-validated past the boundary: Acme recomputes pricing and tax and enforces its own total.

Technical appendix
MCP Tools & Call Sequence
Tool mapping for each wireframe step. Four tools, served by the Noodle Seed–authored acme_bistro server. Concrete request/response JSON lives in api-contract.md.
Browse & Build (Steps 1–3)
Step 1 — Show the menu
READshow_menu— tool + view. Returns the 5-item menu and renders MenuCart.
Design intent: the menu is small and static, so it ships in one read — no pagination, no follow-up call. The items[] array is the model's only source of dish names and prices.
Steps 2–3 — Build & edit the cart
WRITEadd_to_cart— tool + app visibility. Reflects a natural-language addition (item + quantity) into the visible cart.
WRITEremove_from_cart— tool + app visibility. Removes one unit; the widget's − button calls the same tool.
Natural-language parsing: "two margheritas and a lemon tart" becomes add_to_cart{item:"stone_pizza",quantity:2} + add_to_cart{item:"lemon_tart",quantity:1} — the model fills the fields; no UI round-trip. The running total is summed live in the widget (React), not in a tool.
Confirm & Hand off (Step 4 → off-app)
Step 4 — Mint the payment link
OPEN-LINKcreate_checkout— model-visible tool. Returns a signed deep link + summary; ChatGPT opens it.
No payment in-chat. The widget passes a url-safe cart token and the numeric total; create_checkout returns checkoutUrl = https://pay.acme.example/checkout?cart=…&total=…&src=chatgpt (production adds a signed expires_at). The app never sees card data. Acme recomputes pricing/tax and enforces the total past the boundary. No submit_order tool exists by design — fulfilment is Acme's.
