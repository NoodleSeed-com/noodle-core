How to read these wireframes

Solid-border phones are the in-ChatGPT app (the discovery & shortlist loop — no account, no transaction). Dashed-border phones are off-app destinations (Acme's booking flow at book.acme.example) reached only after the handoff. Every card is grounded: the place, "from" price, best-months, region, and reason all come from Acme's own curated catalog and are shown verbatim — the app never invents a destination or a number.

Surface 1 · core

Discovery — a grounded catalog, never a guess

The opening move: turn a fuzzy feeling into four real Acme getaways, each with its own "from" price, best-months window, region, and honest reason. The model narrates which fit the stated vibe; the carousel shows the full curated catalog.

Why it's built this way

UX A traveler at "where should we go?" wants a few credible options with a reason each — not an infinite list. Four cards scan in seconds; one tap shortlists.

ACME Every place, price, and reason is Acme's own catalog data returned verbatim — the app is authoritative because Acme owns all four. TRUST Prices are shown "from $X", never as a quote; discover_getaways returns the whole catalog and never filters on the input, so switching vibe is never a dead end.

Surface 2

Shortlist & re-shape — the deliberation loop

Shortlisting is the "I like this one" gesture — a local widget-state write, not a booking. Changing the vibe, month, or party size re-runs discovery and re-renders the carousel, so the traveler can think out loud without losing context.

Why it's built this way

UX The loop rewards exploration: shortlist, switch vibe, compare, shortlist again. The values you didn't change persist, so a vibe switch never re-asks month or party size.

UI One action per card (Shortlist toggle) and one shell CTA (Continue on Acme) — well inside the ≤2-actions-per-card rule; the carousel is a single track with no nested scroll. TRUST Shortlisting writes nothing off-app: shortlist_getaway is a non-destructive local action, not an account or a cart.

Surface 3 · the funnel boundary

The single, signed, attributable handoff

One deliberate exit — no second track. Continue on Acme calls create_handoff, which builds a signed deep link carrying the shaped trip and the src=chatgpt attribution, then opens Acme's booking flow. Dates, inventory, and payment are Acme's, off-app by design.

Why it's built this way

ACME Acme earns on completed bookings; the app's job is to send pre-shaped, attributable demand. The deep link carries dest · month · pax so nothing is re-typed, plus src=chatgpt so Acme can measure and pay for the funnel.

UI Every value is already URL-safe (id slug · month enum · integer), so the tool substitutes them directly — it never URL-encodes or transforms an input. TRUST The domain is declared in handoff.allowedDomains, so ChatGPT opens it without a safe-link warning; zero credentials cross the boundary.

Technical appendix

MCP Tools & Call Sequence

Every tool that appears in a wireframe, grouped by journey phase, with the intent behind each call. Server: acme_discovery. Three tools, one widget.

Discover & Shortlist (Steps 1–3)

The in-chat loop — grounded, account-free, transaction-free.
1
discover_getawaystool + view
In { vibe, month, travelers } → out { status, vibe, month, travelers, options[] } and renders DiscoveryCarousel. Returns the full curated catalog verbatim (4 destinations); the model narrates fit. Host status: "Finding getaways…" → "Getaways ready". read-only.
2
shortlist_getawaytool + app visibility
In { destination, note } → out { status, destination, note }. Called from inside the carousel when a card's Shortlist is tapped; updates widget view-state. local-action, non-destructive — not a booking.
3
discover_getawaysre-invoke
A natural-language vibe/month/party change re-invokes discovery with the updated input; unchanged values persist so the traveler isn't re-asked. The carousel re-renders in place.

Handoff (Step 4 → off-app)

The single deliberate exit — signed, attributable, credential-free.
4
create_handofftool · open-link
In { destination, destinationName, month, travelers } → out { status, destination, summary, handoffUrl }. Builds https://book.acme.example/plan?dest={destination}&month={month}&pax={travelers}&src=chatgpt by direct substitution of already-URL-safe values. The widget calls it, then opens handoffUrl. Domain declared in handoff.allowedDomains (book.acme.example, acme.example) so the compiler derives ChatGPT's redirect domains. open-action.
